## 0. 先说一个需要你点头的范围问题

「周期记账标记」要出现在四个视图里，但**目前还没有任何入口能创建周期规则**（那张表建好了，规则管理排在第五轮）。
也就是说：如果第三轮只做日历，标记位置永远是空的，你没法在界面上验证它。

我建议第三轮顺带做一个**最小可用的周期规则入口**：新增 / 启用停用 / 删除，只有名称、金额、类型、账户、分类、频率、间隔、起止日期这几个字段，**不做自动生成记录**。
完整规则管理（编辑、下次记账日、和记录联动）仍留在第五轮。

- 选项 A（推荐）：第三轮带上这个最小入口，你能当场看到标记。
- 选项 B：第三轮不碰规则，标记只用自测脚本验证，界面验证推到第五轮。

你不表态我就按 A 做；选 B 的话请直说。

## 2. 组件树、路由与状态

### 2.1 路由

`/calendar` 单路由，视图与锚点日期放 URL 查询串，便于刷新、返回和面包屑：

```
/calendar?view=year&date=2025-06-18
/calendar?view=month&date=2025-06-18
/calendar?view=week&date=2025-06-18
/calendar?view=day&date=2025-06-18
```

- `view` 缺省 `month`，`date` 缺省今天。非法值一律回落，不白屏。
- 面包屑点击 = 切换 `view`，`date` 保持不变（在年视图点「6月」→ view=month 且 date 仍是锚点日）。
- 点日期格 = 同时改 view 和 date。

### 2.2 组件树

```
CalendarPage                     路由容器：解析 URL → 拉数据 → 分发给子视图
├─ CalendarToolbar               面包屑 / 粒度切换 / 前后翻页 / 今天
├─ YearView                      12 格
│  └─ MonthCell                  收 / 支 / 净 / ⟳ / 点击进月
├─ MonthView                     日历格 + 周序号列
│  ├─ WeekLabel                  第 N 周，点击进周视图
│  └─ DayCell                    收 / 支 / 净 / ⟳ / ＋ / 点击进日
├─ WeekView                      7 列
│  ├─ DayColumnHeader            日期 + ⟳ + ＋
│  └─ DayColumn                  当日收/支/净 + 流水摘要
├─ DayView                       当日记录列表（复用记录页的行组件）
│  └─ RecordForm                 复用第二轮的表单，传 defaultDate
└─ RecurringMarker               ⟳ 小图标（title 显示规则名与金额）
```

复用与重构：
- 记录行现在是写在 `RecordsPage` 里的表格，第三轮把它抽成 `features/records/RecordTable.tsx`，记录页与日视图共用，避免两处各写一份。
- `RecordForm` 已经支持 `defaultDate`，第三轮直接透传，不改表单结构。

### 2.3 状态管理

- **URL 是唯一真相**：`view` 与 `date` 只存在查询串里，组件不做本地副本，避免「翻页了但地址栏没变」。
- **数据**用一个自定义 hook `useCalendarData(view, anchorDate)`，返回 `{ days, recurring, records, loading, reload }`，内部按视图算出需要的时间范围再请求；`view`/`date` 变化时重新拉取。
- 全局 store（zustand）不新增：日历是只读展示 + 一个复用表单，没有跨页共享的日历状态。
- 新增记录成功后调用 `reload()` 并 `refreshAccounts()`，停留当前视图。

### 2.4 时间范围与周起点

- 周起点 **周一**（与第一轮方案一致，用 dayjs 的 isoWeek 插件）。
- 年视图：`01-01 ~ 12-31`。
- 月视图：取该月所在完整日历格范围（含上月末与下月初的补位日期），保证格子里补位日期的数据也是真的，而不是 0。
- 周视图：`周一 ~ 周日`。
- 日视图：`当天 ~ 当天`。
- 日期一律 `YYYY-MM-DD` 字符串比较，不经过 `Date` 对象，避免时区漂移。

## 3. 每个视图的 SQL 查询逻辑

### 3.1 一个基础查询：按天聚合

所有视图共用同一条按天聚合的 SQL，范围由视图决定：

```sql
SELECT r.date                                            AS date,
       COALESCE(SUM(CASE WHEN r.type = 'income'  THEN r.amount ELSE 0 END), 0) AS income,
       COALESCE(SUM(CASE WHEN r.type = 'expense' THEN r.amount ELSE 0 END), 0) AS expense,
       COALESCE(SUM(CASE WHEN r.type = 'transfer' THEN r.amount ELSE 0 END), 0) AS transfer,
       COUNT(*)                                          AS count
FROM records r
WHERE r.deleted_at IS NULL
  AND r.date >= ? AND r.date <= ?
GROUP BY r.date
ORDER BY r.date
```

- 转账天然不进 `income` / `expense`，与已确认的口径一致（转账只影响账户余额）。
- 用 `date` 上的既有索引 `idx_records_date`。
- 365 天最坏情况返回 366 行，内存与耗时都可忽略。
- 年视图**不再单独写 month 聚合 SQL**：12 个月的数由日行在内存里滚动汇总，保证四级视图口径绝对一致，不会出现「月视图加起来对不上年视图」。

### 3.2 各种粒度的汇总（纯函数，不落 SQL）

`src/shared/aggregate.ts`：

```ts
sumByMonth(days, year)   // 年视图：12 个月 → { income, expense, net, count }
sumByWeek(days, monday)  // 周视图：7 天 → 同上
sumRange(days, from, to) // 任意区间，日视图汇总条与月视图合计都用它
```

净变化 `net = income − expense`。这三个函数是纯函数，第三轮会进自检脚本，用手工算的预期值对拍。

### 3.3 日视图 / 周视图的明细

明细复用第二轮的 `records.list({ from, to, limit })`（已实现，含分类 / 账户 / 附件联查），不新增 SQL：

- 日视图：`from = to = 当天`。
- 周视图：`from = 周一, to = 周日`，在渲染时按 `date` 分桶到 7 列。

### 3.4 空月份 / 无记录

`GROUP BY` 只会返回有记录的天。补位（把范围内缺失的日期补成 0）在 `useCalendarData` 里做，**只在渲染需要时补**，缺省不补全 366 天，避免无谓开销。

### 3.5 新增 IPC

```
calendar:summary  ({ from, to }) →
{
  days: { date, income, expense, transfer, count }[],
  recurring: { ruleId, name, date, amount, type, accountId }[]
}
```

一次往返把「日聚合 + 周期发生点」都拿回来，视图切换不会连续发多请求。

## 4. 周期记账标记

### 4.1 数据来源

`recurring` 表（第一轮已建，第二轮迁移 002 补了 `to_account_id`）：

```sql
SELECT id, name, amount, type, category_id, account_id, to_account_id,
       frequency, interval, start_date, end_date, next_date, enabled
FROM recurring
WHERE enabled = 1
```

### 4.2 发生点展开规则

`src/shared/recurring.ts` 里的纯函数 `expandOccurrences(rule, from, to)`：

| frequency | 第 k 次发生（k ≥ 0） |
| --- | --- |
| `daily` | `start_date + k × interval` 天 |
| `weekly` | `start_date + k × interval × 7` 天 |
| `monthly` | `start_date + k × interval` 个月，日期取原日；当月没有该日则取当月最后一天 |
| `yearly` | `start_date + k × interval` 年，月日不变；2/29 在平年取 2/28 |

- 只取落在 `[start_date, end_date]` 且落在 `[from, to]` 内的发生点；`end_date` 为空表示长期有效。
- **`next_date` 不参与标记计算**：它只是「下次记账日」的缓存，供第五轮的规则列表显示，避免它一旦过期就让标记悄悄消失。
- 结果按日期分组后随 `calendar:summary` 返回。

### 4.3 四个视图里的显示位置

| 视图 | 位置 | 呈现 |
| --- | --- | --- |
| 年视图 | 月格标题右肩 | `⟳` 小图标，该月有任何发生点就显示；悬停显示「N 条周期规则」 |
| 月视图 | 日期格右上角 | `⟳`；悬停显示规则名与金额 |
| 周视图 | 列头日期右侧 | `⟳`；列内流水区顶部列出当天周期项（虚线框、非真实记录） |
| 日视图 | 记录列表顶部 | 一行虚线卡片「⟳ 周期：房租 −¥2,000.00」，明确标注「仅标记，未生成记录」 |

自测脚本会覆盖：月租规则在某月的发生点、跨月补位（1/31 的规则在 2 月落在 2/28）、
`end_date` 到期后不再标记、停用的规则不产生标记。

## 5. 点某天新增记录：日期预填流程

```
用户在某天格上点「＋」
   → CalendarPage 把该天记进 state: { formDate: '2025-06-18' }
   → 渲染 <RecordForm open record={null} defaultDate="2025-06-18" />
   → 用户填金额/分类/账户，保存
   → 主进程写库（走第二轮已有的 records:create）
   → onSaved: reload() 拉当日数据 + refreshAccounts() 刷新余额
   → 关闭表单，停留在原视图，当前日期格数字立即更新
```

细节：
- 日视图顶部的「＋ 记一笔」同一条路径，`defaultDate` 取当天；当天没有记录时的空状态按钮也一样。
- 周视图点列头「＋」预填该列日期；月视图点格内「＋」预填格子日期；年视图不提供直接新增（避免记错月份），点月格先进月视图。
- 表单里日期字段仍可改，预填只是初值。
- 双击格子 = 与点「＋」等价，给键盘流用户留个快路径。

## 6. 深色模式：收入 / 支出 / 净变化三色对比度

三个数值在同一个格子里并排出现，必须一眼分得开，且两种主题下都达到 **WCAG AA 正文对比度 ≥ 4.5:1**。

新增三个语义色变量（`styles/index.css`），只用于金额正负，不改动其它配色：

| 语义 | 浅色（卡片 `#FFFFFF`） | 对比度 | 深色（卡片 `#1B2128`） | 对比度 |
| --- | --- | --- | --- | --- |
| 收入 `--c-income` | `#1F7A4D` | **5.32:1** | `#6FCF9A` | **8.55:1** |
| 支出 `--c-expense` | `#B23F38` | **5.74:1** | `#F0908A` | **7.00:1** |
| 净变化为正 | 同收入色 | 5.32:1 | 同收入色 | 8.55:1 |
| 净变化为负 | 同支出色 | 5.74:1 | 同支出色 | 7.00:1 |
| 净变化为零 `--c-muted` | `#5F6E7C` | **5.24:1** | `#93A1AE` | 6.7:1 |

对比度按 WCAG 相对亮度公式实算（sRGB 线性化后 `(L1+0.05)/(L2+0.05)`），不是估的。

补充约定：
- 净变化前面带显式符号 `+` / `−`，不靠颜色单独表意（色盲用户也能读）。
- 金额数字用等宽数字（`font-variant-numeric: tabular-nums`），列对齐不抖。
- 当前 `--c-muted` 是 `#6B7A88`（对白 4.41:1，略低于 4.5），顺手调到上表的 `#5F6E7C`；这会让全应用次要文字更清楚一点，属于全局微调。
- 记录列表里的支出目前是中性色，日历格子里三色并排容易糊，所以日历内统一用语义色；记录列表是否跟着改，等第三轮做完实际看一眼再定（不在这轮强改）。
