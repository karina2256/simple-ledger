## 一、上架前必须先解决的三个门槛

### 1. 代码签名证书（最影响观感，也最卡上架）

**现状**：没有签名，Windows SmartScreen 会拦一下（「Windows 已保护你的电脑」），
微软商店 / 部分分发渠道会直接拒绝未签名包。

**你要做**：
1. 买证书。三种档位：
   - **OV 代码签名证书**（约 ¥1000–2500/年）：能消除「未知发布者」，SmartScreen 需要积累声誉（几十到几百次下载后不再提示）。
   - **EV 代码签名证书**（约 ¥2500–5000/年）：硬件 UKey，签名后 SmartScreen **立即**不提示。上架首选。
   - **Azure Trusted Signing**（按量计费，约 $10/月）：云签名、免 UKey，个人开发者目前需要一定资质审核。
   - 常见签发机构：DigiCert、Sectigo、Certum（Certum 开源项目有折扣）。
2. 拿到证书后有两种接法：
   - **证书 + 密码**：设环境变量 `CSC_LINK`（.pfx 路径或 base64）与 `CSC_KEY_PASSWORD`，`electron-builder` 会自动签名 —— **不用改一行代码**。
   - **EV 硬件 UKey**：签名要调厂商的签名工具（如 SafeNet），electron-builder 支持通过 `sign` 钩子接自定义命令；这条要改 `electron-builder.yml` 加 `win.sign` 配置，可以交给我做。
3. 验签：`Get-AuthenticodeSignature release\win-unpacked\记账簿.exe` 应显示 `Valid`。

> **这一项我做不了**：需要实名、付费、私钥。代码侧我已经把 `artifactName` / `appId` / 图标都备好了，你拿到证书我十分钟内就能接上。

### 2. 版本号与产品信息

**现状**：`0.1.0`，`appId: com.dailyledger.app`，`productName: 记账簿`。

**你要做**：确认三件事——
- `appId` 是否要改成你自己的域名反写（如 `com.yourname.ledger`）。**上架后不能改**，改了等于新应用。
- 版本号策略：建议上架前升到 `1.0.0`。
- 发布者名称（签名证书里的公司/个人名）会显示在安装提示里。

### 3. 隐私政策页 + 软件说明（商店必填）

**好消息**：这个软件**不联网、不采集任何数据**，隐私政策可以写得非常短（这反而是卖点）。

**你要做**：
- 准备一个可公开访问的隐私政策 URL（可以放在你的官网上，或 GitHub Pages）。
- 内容要点：不采集、不上传、无账号体系、无第三方 SDK、数据只在本机、如何删除数据（删数据目录即可）。
- 需要英文版的话我可以给你出一份模板。

## 二、各渠道的上架材料与步骤

### A. 微软商店（Microsoft Store）—— 最省事的 Windows 渠道

**为什么选它**：免费开发者账号（个人）、自动更新由商店托管、用户信任度高。

**你要做**：
1. 注册 **Microsoft Partner Center** 开发者账号（个人约 ¥120 一次性，或公司账号）。
2. 用 **MSIX** 打包（商店只收 MSIX/APPX）：
   - 我可以加一个 `electron-builder` 的 `appx` 或 `msix` target；
   - 注意：**带原生模块（better-sqlite3 / onnxruntime-node）的打包需要仔细验证**，商店对 MSIX 里的原生 DLL 有额外要求；
   - 商店还要求「打包的应用必须签名」——签名证书那步绕不开。
3. 准备商店素材：应用名、分类（财务/效率）、3–10 张截图（我可以从 `docs/screenshots/` 挑）、1 张 300×300 图标、简短描述与详细描述、隐私政策 URL。
4. 提交审核（通常 1–3 个工作日）。

> 需要我做的话：`msix` 打包配置 + 素材整理，说一声就开工。

### B. 官网直接下载（推荐，和商店并行）

**为什么**：商店抽成、审核慢；官网直销能拿到用户邮箱、能自主更新。

**你要做**：
1. 买域名（如 `jizhangbu.app` / `你的名字.com`），约 ¥50–100/年。
2. 选托管：
   - **Cloudflare Pages / GitHub Pages**：免费，够用；
   - **Vercel / Netlify**：免费额度也够。
3. 上传一个下载页：
   - 三个下载按钮（免安装 exe / 安装版 exe / MSI）；
   - 版本号与更新日志；
   - 隐私政策链接；
   - **文件放哪**：116MB 的安装包不适合放 Pages（有体积限制），建议放 **Cloudflare R2 / 阿里云 OSS / 腾讯云 COS**（几毛钱一个月），页面只放链接。
4. **检查更新（代码侧已经做完了，只差一个地址）**：
   软件已经接好「读静态 JSON 清单 → 比对版本号 → 提示新版本并给下载链接」，**不用再改代码**。你只要：
   - 把一个 `update.json` 放到任意可公开访问的地址（对象存储 / Pages 都行）：
     ```json
     {
       "version": "1.1.0",
       "url": "https://你的域名/download",
       "notes": "新增预算与汇总图表"
     }
     ```
   - 把地址告诉我，我写进 `src/main/services/security.service.ts` 的 `DEFAULT_UPDATE_URL`（下次打包生效）。
   - 以后发新版**只改这个 JSON 的 version**，不用重发客户端。

   为什么不做静默自动升级：Windows 上静默安装要求代码签名，而且一个离线记账工具突然自己换版本会让用户不安。现在的行为是「告诉你有没有新版 + 给个链接」，可控且诚实。
   如果你坚持要真·自动更新（下载安装包并调起安装），那就得先解决签名（见第 1 条），我再接 `electron-updater`。

### C. 其他 Windows 渠道（可选）
- **Winget**：提一个 PR 到 `microsoft/winget-pkgs`，只要有个公开下载 URL 就行，零成本、有技术用户群。
- **Chocolatey / Scoop**：同理，适合开发者用户。
- 这三个都只是「写清单文件 + 提 PR」，我可以帮你生成内容。

### D. 手机端（如果以后要）
现在这是 Electron 桌面应用，**上不了 App Store / 应用宝**。要上手机就得重写成 React Native / Flutter，或用 Tauri Mobile —— 那是另一个项目，不是「打包一下」能解决的。

## 三、可以立刻做的「软上架」（今天就能发）

不需要证书、不需要审核：

1. **GitHub Release**：建仓库 → 把 `release/` 里的三个包发到 Release → 得到永久下载链接。
   - 优点：免费、有版本历史、`electron-updater` 可以直接用 GitHub Releases 当更新源（**我可以配好**）；
   - 缺点：下载页是英文的、GitHub 在国内访问不稳。
2. **网盘 + QQ/微信**：给朋友小范围分发（已经做过一次）。
3. **小众软件 / 少数派 / V2EX** 发帖：软件的「完全离线 + 不上传」是很好讲的故事。
