## 1. 技术方案

### 1.1 选型

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 壳 | Electron 34.x | 主进程 + 渲染进程，单实例锁，托盘常驻 |
| 构建 | electron-vite | 基于 Vite，统一编译 main / preload / renderer，主进程与渲染进程都支持热更新 |
| 语言 | TypeScript 5.x（strict） | 全链路类型，IPC 通道有共享类型定义 |
| UI | React 18 + React Router（HashRouter） | 打包后 `file://` 协议下 HashRouter 最稳 |
| 样式 | Tailwind CSS 3.x + CSS 变量 | 深色/浅色主题通过 `<html class="dark">` 切换 |
| 图表 | ECharts 5 + echarts-for-react | 饼图 / 柱状图 / 折线图 |
| 状态 | Zustand | 轻量，按领域拆 store |
| 日期 | dayjs + isoWeek 插件 | 周视图以周一为起点 |
| 数据库 | better-sqlite3 12.x | 同步 API，写入即落盘，主进程独占 |
| 打包 | electron-builder | 产出 `nsis` 安装包、`msi` 安装包、`portable` 免安装 exe |

安装后需要 `@electron/rebuild` 针对 Electron 的 ABI 重编译 better-sqlite3（electron-builder 的 `postinstall` 会自动做，方案里写成 `electron-builder install-app-deps`）。这是本项目唯一有“编译风险”的一环，第二轮会第一时间验证；若预编译包缺失会先暴露出来，不会拖到第六轮。

### 1.2 进程与安全边界

```
┌─────────────────────────── Electron 主进程（Node） ───────────────────────────┐
│  app 生命周期 / 单实例锁 / BrowserWindow / Tray / 原生菜单 / 对话框             │
│  SQLite 连接（唯一持有者）、迁移、完整性校验、备份、附件文件读写                │
│  ipcMain.handle('db:xxx')  ← 全部业务写在这里，渲染进程不碰 fs / db             │
└───────────────────────────────────────────────────────────────────────────────┘
                                   ▲  contextBridge 暴露的白名单 API
                                   │  （contextIsolation: true, nodeIntegration: false,
┌─────────────────────────── 渲染进程（Chromium） ──────────────────────────────┐
│  React 页面 / 组件 / ECharts / Tailwind                                       │
│  window.api.records.list(...) 等强类型方法；无 Node 能力                      │
└───────────────────────────────────────────────────────────────────────────────┘
```

- `preload` 只暴露 `window.api`，每个方法对应一条 IPC 通道，通道名与 TS 类型集中在 `src/shared/ipc.ts`。
- 渲染进程 `sandbox: true`，禁用 `webview`，`webSecurity` 保持开启，不加载任何远程资源（字体、CDN 全部本地打包）→ 断网可用。
- 窗口关闭（X）不退出：`win.on('close')` 拦截并 `hide()`，只有托盘「退出」或 `app.before-quit` 标志位才真正退出。

### 1.3 数据落盘策略（对应「数据永不丢失」）

| 措施 | 做法 |
| --- | --- |
| 存储引擎 | SQLite 文件 `<数据目录>/daily-ledger.db` |
| 日志模式 | `journal_mode = WAL`（崩溃恢复更稳，读写不互相阻塞） |
| 同步级别 | `synchronous = FULL`（每次事务提交即 fsync，满足「每次写入立即落盘」） |
| 外键 | `foreign_keys = ON` |
| 启动校验 | `PRAGMA quick_check`，失败时弹窗提示并给出备份文件路径 |
| 迁移 | `PRAGMA user_version` + 顺序迁移脚本数组，只升不降 |
| 备份 | 设置页「手动备份数据库」→ 先 `wal_checkpoint(TRUNCATE)` 再复制为 `backup/daily-ledger-YYYYMMDD-HHmmss.db`，不做自动备份 |
| 数据目录 | 首次启动引导选择，记在 `<userData>/config.json`（引导文件，独立于数据库） |
| 附件 | 复制到 `<数据目录>/attachments/YYYY/MM/<uuid>.<ext>`，数据库只存相对路径 → 数据目录整体搬家不丢图 |

**金额一律以「分」为整数存储**（`amount_cents INTEGER`），显示时除以 100。这是避免浮点误差的硬性决定，所有汇总口径统一。

### 1.4 备注颜色规则

`colorIndex = FNV1a(note.trim()) % palette.length`，调色板 12 色（柔和低饱和，浅/深色主题各一套映射）。同一备注字符串必然得到同一颜色，无需存库、无需维护表。

## 3. 数据模型（SQLite DDL 草案）

设计约定：
- 主键 `id TEXT`（UUID v4），便于附件、备份、合并场景下不冲突。金额 `INTEGER`（分）。
- 时间戳统一 `INTEGER`（Unix 毫秒）；业务日期 `date TEXT`（`YYYY-MM-DD` 本地日期，避免时区漂移）。
- 软删除：`deleted_at INTEGER NULL`，支持「撤销删除」；列表查询一律带 `deleted_at IS NULL`。

```sql
PRAGMA foreign_keys = ON;

-- 账户
CREATE TABLE accounts (
  id              TEXT PRIMARY KEY,
  name            TEXT NOT NULL UNIQUE,
  icon            TEXT NOT NULL DEFAULT 'wallet',
  color           TEXT NOT NULL DEFAULT '#64748B',
  initial_balance INTEGER NOT NULL DEFAULT 0,   -- 分
  sort_order      INTEGER NOT NULL DEFAULT 0,
  created_at      INTEGER NOT NULL,
  updated_at      INTEGER NOT NULL,
  deleted_at      INTEGER
);

-- 分类（parent_id 为空即一级）
CREATE TABLE categories (
  id         TEXT PRIMARY KEY,
  parent_id  TEXT REFERENCES categories(id) ON DELETE CASCADE,
  name       TEXT NOT NULL,
  icon       TEXT NOT NULL DEFAULT 'tag',
  color      TEXT NOT NULL DEFAULT '#64748B',
  type       TEXT NOT NULL CHECK (type IN ('income','expense')),
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  deleted_at INTEGER,
  UNIQUE (parent_id, name, type)
);
CREATE INDEX idx_categories_parent ON categories(parent_id);

-- 记录
CREATE TABLE records (
  id            TEXT PRIMARY KEY,
  date          TEXT NOT NULL,                  -- YYYY-MM-DD
  amount        INTEGER NOT NULL CHECK (amount >= 0),  -- 分
  type          TEXT NOT NULL CHECK (type IN ('income','expense','transfer')),
  category_id   TEXT REFERENCES categories(id) ON DELETE SET NULL,
  account_id    TEXT REFERENCES accounts(id)   ON DELETE SET NULL,
  to_account_id TEXT REFERENCES accounts(id)   ON DELETE SET NULL,  -- 仅 transfer 用
  note          TEXT NOT NULL DEFAULT '',
  note_color    TEXT,                           -- 可空；空则由 note 哈希推导
  tags          TEXT NOT NULL DEFAULT '[]',     -- JSON 数组字符串
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL,
  deleted_at    INTEGER
);
CREATE INDEX idx_records_date        ON records(date);
CREATE INDEX idx_records_account     ON records(account_id);
CREATE INDEX idx_records_category    ON records(category_id);
CREATE INDEX idx_records_type_date   ON records(type, date);
CREATE INDEX idx_records_note        ON records(note);

-- 收据附件
CREATE TABLE attachments (
  id         TEXT PRIMARY KEY,
  record_id  TEXT NOT NULL REFERENCES records(id) ON DELETE CASCADE,
  file_path  TEXT NOT NULL,                     -- 相对数据目录，如 attachments/2025/06/xxx.png
  file_name  TEXT NOT NULL,
  file_type  TEXT NOT NULL,                     -- image/png 等
  file_size  INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL
);
CREATE INDEX idx_attachments_record ON attachments(record_id);

-- 周期记账规则
CREATE TABLE recurring (
  id          TEXT PRIMARY KEY,
  name        TEXT NOT NULL,
  amount      INTEGER NOT NULL,
  type        TEXT NOT NULL CHECK (type IN ('income','expense','transfer')),
  category_id TEXT REFERENCES categories(id) ON DELETE SET NULL,
  account_id  TEXT REFERENCES accounts(id)   ON DELETE SET NULL,
  frequency   TEXT NOT NULL CHECK (frequency IN ('daily','weekly','monthly','yearly')),
  interval    INTEGER NOT NULL DEFAULT 1,
  start_date  TEXT NOT NULL,
  end_date    TEXT,
  next_date   TEXT NOT NULL,
  enabled     INTEGER NOT NULL DEFAULT 1,
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL
);
CREATE INDEX idx_recurring_next ON recurring(enabled, next_date);

-- 预算
CREATE TABLE budgets (
  id          TEXT PRIMARY KEY,
  category_id TEXT REFERENCES categories(id) ON DELETE CASCADE,  -- NULL = 总预算
  amount      INTEGER NOT NULL,
  period      TEXT NOT NULL CHECK (period IN ('monthly','yearly')),
  year        INTEGER,          -- 为空表示“每年都适用”
  month       INTEGER,          -- 仅 monthly 用
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL,
  UNIQUE (category_id, period, year, month)
);

-- 设置（键值对）
CREATE TABLE settings (
  key        TEXT PRIMARY KEY,
  value      TEXT NOT NULL,     -- JSON 序列化
  updated_at INTEGER NOT NULL
);
```

预设数据（首次启动写入，`settings.seeded` 防重复）：

- 账户：微信、支付宝（`initial_balance = 0`）。
- 支出分类：餐饮（早餐/午餐/晚餐/外卖/零食）、交通（公交地铁/打车/加油/停车）、购物（网购/日用/服饰/数码）、居住（房租/水电燃气/物业/宽带）、娱乐（影音会员/游戏/旅行/聚会）、医疗（挂号/药品/体检）、教育（书籍/课程/培训）、人情（红包/礼物/请客）、其他。
- 收入分类：工资（月薪/奖金）、理财（利息/基金/股票）、兼职、红包、退款、其他。
- 默认设置：`currency = CNY`、`showUsd = false`、`usdRate = 7.2`、`theme = light`、`autoGenerateRecurring = false`、`advancedMode = false`。

### 3.1 已确认的口径（2025-06-18 确认）

1. **记录类型与分类并存** → 采用方案 A：`records.type` 只保留 `income / expense / transfer` 作为会计口径；新增 `channel` 字段存场景（网购 / 线下 / 饮食 …），可自定义。
   字段写法加进 `records` 建表语句：

   ```sql
   channel TEXT NOT NULL DEFAULT 'offline'   -- online / offline / dining / ... 键值可自定义
   ```

   `channel` 用字符串键，配合 `settings` 里的 `channels` JSON 列表维护名称、图标与排序（不新增表）。汇总一律按 `type` 计算；列表展示与筛选可按 `channel`。
2. **转账不计入收支** → 转账只影响账户余额，不进入任何总收入 / 总支出 / 结余口径，日历格也不显示转账金额；日视图的当日明细里可以看到转账记录本身。
3. **工作区路径** → `C:\Users\34123\Desktop\记账簿`。
4. **清理数据的口径**（第二轮补充确认，见 4.9）：范围按时间（年 / 自定义区间 / 全部时间），内容分「仅明细」与「全部」两档预设，且可逐项勾选；清理前强制自动备份。详细口径写在 4.9。

### 3.2 关键业务口径（提前定死，保证汇总准确）

- **账户余额** = `initial_balance + Σ(收入到该账户) − Σ(支出自该账户) + Σ(转出至该账户) − Σ(自该账户转出)`，仅统计 `deleted_at IS NULL`。
- **月度汇总**：`总收入 = Σ income`；`总支出 = Σ expense`；`结余 = 总收入 − 总支出`；转账默认双边不计入（见问题 3）。
- **环比** `(本月 − 上月) / 上月`，上月为 0 时显示「—」而非 ∞。
- **每日趋势**：以 `date` 分组，补齐当月无记录日期为 0，折线不断档。
- **预算进度** = `当期已支出 / 预算金额`；≥80% 黄色提醒，>100% 红色超支提醒。

口径与安全约定：

| 项 | 做法 |
| --- | --- |
| 时间口径 | 按 `records.date` 判断，区间含首尾，不受时区影响 |
| 「仅明细」 | 只删 `records` + `attachments`，账户、分类、规则、预算、设置全留 → 是最常用的档位 |
| 「明细 + 规则 + 预算」 | 明细之外，删掉 `start_date` 落在范围内的周期规则，以及 `year/month` 落在范围内的预算 |
| 「全部数据」 | 上面全部 + 账户、分类、设置，等于恢复出厂；执行后回到首次启动引导 |
| 附件处理 | 默认把文件移进 `backup/attachments-<时间戳>/`，备份目录里还找得回；勾选「彻底删除」才真删 |
| 强制备份 | 每次清理前先 `wal_checkpoint` 再复制数据库到 `backup/`，此项不可关闭 |
| 二次确认 | 必须手动输入「确认清理」，不用「确定/取消」式弹窗 |
| 撤销 | 清理不可在应用内撤销，恢复方式是关掉应用、用备份文件覆盖当前数据库（README 会写清步骤） |
| 空间回收 | 事务提交后执行 `VACUUM`，文件体积真降下来（数百 MB 级别才有必要，设置里可勾选跳过） |
| 越界保护 | 有未完成的撤销删除、或上次备份失败时，禁止执行清理 |
| 入口 | 设置页「高级操作」区域内，需先打开高级操作开关才可见/可用 |

执行顺序（避免出现删了库、剩下一堆孤儿文件）：先备份 → 移动附件文件到备份目录 → 开事务删数据 → 提交 → `VACUUM`。事务失败则把附件移回原处。
