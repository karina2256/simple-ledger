# 动效 报告

状态：**已完成，`verify:motion` 34/34 通过（含炫技层落地、滚动驱动、View Transition、弹簧过冲、减少动态效果）。**

目标从「克制可信的账本」改成了「Apple 产品页那种观感」。做法是加一层**炫技层**，
上一轮的克制层保留为「标准档」——两档都留着，设置里可切。
全程**零依赖**：不用 framer-motion / GSAP / Lottie，靠 Chromium 132 的原生能力实现。

---

## 1. 三档强度

| 档位 | `data-motion` | 内容 |
| --- | --- | --- |
| **炫技（默认）** | `showcase` | 环境渐变、毛玻璃、滚动揭示、英雄区钉住、3D 倾斜高光、View Transition 转场、主题圆形擦除、弹簧数字、粒子庆祝 |
| 标准 | `standard` | 上一轮的克制层：时长/缓动统一、错峰入场、按压反馈、校验抖动，无位移特效与背景虚化 |
| 极简 | `minimal` | 动画时长压到 0.01ms，等同系统「减少动态效果」 |

设置入口：设置 → 动效 → 强度（`SettingsPage`，写入 `settings.motion`；设置表是 key-value，加字段不需要迁移）。
`prefers-reduced-motion: reduce` **永远优先**于档位设置。

## 2. 炫技层逐项实现

| 效果 | 手段 | 关键参数 |
| --- | --- | --- |

## 3. 弹簧曲线是算出来的

三条 `linear()` 曲线由阻尼弹簧方程采样得到，不是手填贝塞尔：

```
y(x) = 1 - e^(-ζω₀x) · [cos(ω_d x) + (ζω₀/ω_d)·sin(ω_d x)]
采样区间 T = 4.6 / (ζω₀)   // 振幅衰减到 1%
```

| 变量 | stiffness / damping | 峰值 | 用途 |
| --- | --- | --- | --- |
| `--x-soft` | 150 / 24 | 1.00 | 大表面、页面、环境 |
| `--x-snappy` | 300 / 22 | 1.075 | 按钮、指示条、卡片 |
| `--x-bouncy` | 200 / 12 | 1.227 | 弹窗、提示条、庆祝 |

JS 侧的 `SPRING_SAMPLES` 就是 `--x-snappy` 那张采样表，所以「金额数字回弹」与「CSS 回弹」手感一致。

## 5. 这一轮抓到并修掉的 4 个真问题

### 坑 1：`<tr>` 上的 `position: relative` 会算歪表格列宽

给行加「左侧色条」时用了 `position: relative` + `::before`。结果日期列从 112px 被压到 96px、行高从 42px 涨到 61px。
用**对照实验**定位（探针里依次移除 `.cinema-row`、`.m-rise` 再测量）：

```
base        : 日期列 96px  行高 61px
去掉 cinema-row : 日期列 112px 行高 42px   ← 恢复
```

结论：Chromium 把行内的绝对定位伪元素算进了列宽。改成 `inset box-shadow` 画侧条即可，并在 CSS 里写了警告。
这条已经固化成断言「动效层没有挤坏表格列宽」，以后回归会直接被抓住。

### 坑 2：`NavLink viewTransition` 在声明式路由下是空转

React Router 的 View Transition 能力挂在 `ViewTransitionContext` 上，只有**数据路由**（`RouterProvider`）才提供，
`<HashRouter>` 下 `<NavLink viewTransition>` 不会调用 `document.startViewTransition`（探针实测调用 0 次）。
改成自己接管：`Link` + `withViewTransition(() => navigate(to))`，内部用 `flushSync` 提交路由状态。

### 坑 3：页面不可滚动时，进度条会显示成「全满」

滚动时间线在不可滚动的容器上不活跃，动画不生效，元素就露出了基础样式——一条全宽渐变条。
修法：基础状态给 `transform: scaleX(0)`。

### 坑 4：玻璃太透会把表格数字染色

底色从 `--c-card` 的 74% 提到 80%，光斑不透明度 0.5 → 0.46（深色 0.42 → 0.40）：
既保留「底下有东西在流动」的感觉，又不至于让金额读数发花。

另外顺手修掉了上一轮遗留的输入框定宽失效问题（`inputBase` 的 `w-full` 覆盖 `w-40/w-48/w-24/w-52/w-32`，
详见上一版报告），这次同样用对照方式确认过。

## 6. 性能与降级

- 只动 `transform` / `opacity` / `filter`，不动宽高边距；光斑与渐变都是合成层，漂移不触发重排。
- `backdrop-filter` 是这里最贵的一项（侧栏 + 顶栏 + 每张卡片）。十来个玻璃面同时存在时，
  低配机器上滚动可能掉帧——所以「标准档」会直接把 `backdrop-filter` 关掉（`.cinema-glass` 回退成实色卡片）。
- 滚动揭示只给**短元素**（卡片）用；表格行仍然用时间驱动的错峰入场，
  避免 500 行列表产生 500 条 `view()` 时间线。超长元素（比视口还高）**不能**用 `entry` 区间，
  那样动画永远播不完，会卡在半透明。
- 系统「减少动态效果」或「极简档」下，光斑动画直接 `animation: none`，不留常驻动画。

## 7. 已知取舍

- **没做滚动钉住的多段叙事**（Apple 产品页那种「滚一屏换一个镜头」）：这需要长页面 + 内容分段，
  记账工具的页面结构是「列表 + 表单」，硬塞会牺牲可用性。
- **表格行只做入场 + 悬停**：删除/撤销时没有行的退出动画（列表按 id 复用，需要额外的「离开中」状态）。
- **翻页不做方向性滑动**：日历翻月统一用轻落位 + View Transition，避免快速连点时内容来回甩。
- **退场动画有边界**：`Modal` 自己实现了退场，但父组件若直接卸载（例如删除确认弹窗），退场来不及播；
  进场不受影响。
