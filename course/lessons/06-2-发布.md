## 一、发布的三个问题

### 1.1 全景

```
① 放哪？    →  文件托管（服务器在哪）
② 怎么给？  →  下载链接 + 安装体验（用户信不信你）
③ 怎么被找到？→  SEO + 传播（陌生人怎么知道你）
```

**很多人只想到 ①**，然后发现"我把安装包传上去了，怎么没人下载"——因为 **② 和 ③ 没解决**。

### 1.2 现实比喻：开一家实体店

| 开店 | 发布软件 |
| --- | --- |
| 租个铺面 | **文件托管**（服务器） |
| 招牌、门面装修 | **官网**（用户第一印象） |
| 营业执照 | **代码签名**（让系统信任你） |
| 发传单、挂路牌 | **SEO + 传播** |
| 顾客进门后能不能买到 | **下载体验**（链接是否有效、能不能装上） |

**少了任何一环，店都开不成。**

## 二、问题 ①：放哪（文件托管）

### 2.1 为什么不能直接放在网站里

安装包 **116 MB**，而代码托管平台通常限制单文件几十 MB。**所以必须分开**：

```
官网（几 KB 的 HTML） → 放在网站托管
安装包（116 MB）      → 放在文件托管（对象存储 / Release）
```

### 2.2 三种方案对比

| 方案 | 费用 | 国内访问 | 适合 |
| --- | --- | --- | --- |
| **GitHub Releases** | 免费 | 不稳定 | **先跑起来**，或面向国外用户 |
| **对象存储**（阿里云 OSS / 腾讯云 COS / Cloudflare R2） | 几毛～几元/月 | 快（国内节点） | 面向国内用户 |
| **自己的服务器** | 服务器月租 | 取决于机房 | 已经有服务器的情况 |

**建议**：**先用 GitHub Releases 跑通全流程**（0 成本、5 分钟），有真实用户了再换成对象存储。

### 2.3 项目里已经留好了位置

**打开 `website\main.js`，最上面就是你要改的地方**：

```js
var DOWNLOADS = {
  portable: '',  // 例：'https://github.com/你的账号/记账簿/releases/download/v0.1.0/daily-ledger-0.1.0-portable.exe'
  setup: '',     // 例：'.../daily-ledger-0.1.0-setup.exe'
  msi: ''        // 例：'.../daily-ledger-0.1.0-installer.msi'
}
```

**注意一个重要设计**：**这三个值留空时，网站不会跳到 404**——它会原地显示一句提示。

**看它是怎么处理的**（`main.js` 里的逻辑）：

```js
var url = DOWNLOADS[link.dataset.download]
if (url) {
  link.href = url            // 配了就用真实链接
  ...
  return
}
// 没配：不要跳到 404，原地说明
link.addEventListener('click', function (event) {
  event.preventDefault()
  tip.textContent = '下载地址还没配置：把 main.js 顶部 DOWNLOADS 里的三个链接换成真实安装包地址即可。'
})
```

**这是一个值得学的产品细节**：**"未配置"应该给出可理解的提示，而不是让用户看到一个 404 页面。**

## 三、问题 ②：怎么给（安装体验与信任）

### 3.1 最大的拦路虎：没有代码签名

**这是发布环节最现实的问题。** 用户双击你的安装包，会看到：

> **Windows 已保护你的电脑**
> Windows Defender SmartScreen 阻止了一个无法识别的应用启动。

**用户的第一反应**：**"这是病毒吧？"** → 关掉 → 删掉文件。

**为什么会出现这个**：因为软件**没有代码签名证书**。

### 3.2 代码签名是什么

**现实比喻：营业执照 + 防伪印章。**

| | 没有签名 | 有签名 |
| --- | --- | --- |
| 系统看到 | "一个来路不明的程序" | "**XX 公司**签发的程序，签名有效" |
| 用户看到 | **蓝色恐吓弹窗** | 正常的 UAC 确认 |
| SmartScreen | 拦截 | **不拦截**（EV 证书立即可信） |

**签名做了什么**：用你的**私钥**给安装包做数字签名。Windows 用公钥验证"这个包确实是你发的，而且没被篡改过"。

### 3.3 三种证书（真实成本）

| 类型 | 价格 | 效果 |
| --- | --- | --- |
| **没有证书** | ¥0 | 每次都弹蓝色警告，**可能流失大半用户** |
| **OV 代码签名** | 约 ¥1000–2500/年 | 有签名，但 SmartScreen 需要**积累声誉**（下载量上去才不警告） |
| **EV 代码签名** | 约 ¥2500–5000/年 | **立即**不警告（硬件 UKey） |
| Azure Trusted Signing | 按量计费 | 云签名，免 UKey，需要一定资质 |

**这是个真实的商业决策**：

- **如果只是给朋友用**：不签名也行，**提前告诉他"点更多信息 → 仍要运行"**（这就是分享包里"使用说明"写了这条的原因）。
- **如果要给陌生人用**：**没有签名会流失大量用户**。几百到几千元一年，是"正经发布"的硬门槛。

### 3.4 这件事的技术接入很简单

**好消息**：签名**不需要改代码**。`electron-builder` 支持通过环境变量自动签名：

```powershell
$env:CSC_LINK = "证书文件.pfx 的路径"      # 或 base64 内容
$env:CSC_KEY_PASSWORD = "证书密码"
npm run build:win
```

**跑完之后验证签名**：

```powershell
Get-AuthenticodeSignature release\win-unpacked\记账簿.exe | Select-Object Status, SignerCertificate
```

**预期看到**：`Status = Valid`。

**所以"签名"这件事的难点不在技术，而在**：
1. 要**实名**（个人或公司）
2. 要**付费**
3. 拿到私钥后要**妥善保管**（泄露了别人能冒充你发布恶意软件）

### 3.5 用户第一次打开时的完整体验（要提前设计）

**记账簿项目里已经处理了这件事**——你可以在官网首页看到：

> **第一次打开可能看到 Windows 蓝色警告，是正常的**
> 这个软件还没购买代码签名证书，所以 Windows SmartScreen 会拦一下：点「**更多信息**」→「**仍要运行**」即可，不是病毒。

**这个提示值得学**：

| 做法 | 效果 |
| --- | --- |
| **主动说明** | 用户知道"这是预期的"，不会以为中毒 |
| 措辞具体 | 明确告诉他点哪两个按钮（更多信息 → 仍要运行） |
| **顺便解释原因** | "还没买代码签名证书"——**诚实且合理** |

**如果你的软件没有签名，这个提示是必须的。** 否则用户会在第一步就流失。

## 四、问题 ③：怎么被找到

### 4.1 先明确一个残酷事实

> **"上线了"不等于"有人能找到"。**

**搜索引擎不会自动发现你的网站。** 需要三件事：

| 步骤 | 做什么 |
| --- | --- |
| **① 技术准备** | 网站里要有正确的 SEO 元素（下面详讲） |
| **② 主动提交** | 去各搜索引擎的站长平台提交网址和 sitemap |
| **③ 有内容** | 别人搜"问题"时能看到你的页面 |

**第 ③ 条最关键**：**没人搜你的产品名**（因为没人知道），大家搜的是**问题**。

### 4.2 项目里的 SEO 已经做好了

**看官网自检的结果**：

```powershell
cd "C:\Users\34123\Desktop\记账簿"
node scripts/verify-site.mjs 2>&1 | Select-String "官网自检"
```

**实测：35/35 通过。** 它检查了这些（这是真实清单）：

| 检查项 | 作用 |
| --- | --- |
| `title`（15–70 字） | 搜索结果里的蓝色标题 |
| `meta description`（60–160 字） | 搜索结果里的两行摘要 |
| `keywords` | 关键词（现在权重低，但填了没坏处） |
| `canonical` | 告诉搜索引擎"正式地址是哪个"（防重复内容） |
| `robots: index, follow` | 允许收录 |
| **Open Graph 标签** | **分享到微信 / QQ 时的预览卡片**（标题 + 描述 + 图片） |
| **结构化数据 `SoftwareApplication`** | 让引擎知道"这是 Windows 财务软件、免费" |
| `h1` 唯一、`h2` 分层 | 内容结构清晰 |
| 图片 `alt`、懒加载 | 无障碍 + 图片搜索 |
| 正文 > 2500 字 + 6 组问答 | **让引擎有内容可抓**（长尾关键词来源） |
| `sitemap.xml` + `robots.txt` | 站点地图与爬虫规则 |

**这些不是"可选优化"，而是"能不能被收录"的基础。**

### 4.3 主动提交（这一步只能你做）

**技术准备好之后，要去告诉搜索引擎"我存在"**：

| 搜索引擎 | 入口 | 要做什么 |
| --- | --- | --- |
| **Google** | Search Console | 验证所有权（DNS 或 HTML 文件）→ 提交 sitemap → 用"网址检查"请求收录 |
| **Bing** | Webmaster Tools | 同上（国内可访问） |
| **百度** | 资源平台 | 同上，但**未备案的站点收录很差** |

**"验证所有权"是什么**：引擎给你一段代码或一个文件，让你放到网站上，用来证明"这个站是你的"。**需要你的账号，我做不了。**

### 4.4 真正的决定因素：内容

**用户搜的是问题，不是你的产品名**。所以你要写内容，围绕这些词：

| 别人会搜的 | 你可以写的 |
| --- | --- |
| 微信账单怎么导出成 Excel | 「微信账单导出 Excel 的完整步骤」 |
| 记账软件哪个不上传数据 | 「为什么大多数记账 App 要看你的数据」 |
| 本地记账软件推荐 | 「几款本地记账工具对比」 |
| 账单截图怎么自动记账 | 「用截图自动记账是怎么实现的」 |

**这些内容放在官网上，就是一个"教程"栏目**（每篇一个 HTML 页面），是**长期带来流量**的东西。

**传播渠道**（比 SEO 见效快）：

| 渠道 | 特点 |
| --- | --- |
| 少数派 / 小众软件 | 收录好，用户精准 |
| V2EX「分享创造」 | 技术用户，反馈质量高 |
| 知乎回答 | 长尾流量 |
| B 站 / 小红书 | **短视频往往比搜索带来更多用户** |

## 五、检查更新：为什么不做静默升级

### 5.1 项目里的实现

**看 `security.service.ts`**：

```ts
/**
 * 检查更新：读一个静态 JSON 清单，形如
 *   { "version": "1.1.0", "url": "https://你的站点/download", "notes": "修了 XX" }
 *
 * 为什么不做「静默自动升级」：Windows 上静默安装要求代码签名，
 * 而且离线记账工具突然自己换版本会让用户不安。这里是「告诉你有没有新版 + 给个链接」。
 */
const DEFAULT_UPDATE_URL = ''
```

**它在做的事**：读一个 JSON → 比对版本号 → 有新版本就提示 + 给链接。

**用户看到的**（设置 → 关于 → 检查更新）：

```
发现新版本 1.1.0（当前 0.1.0）    [去下载]
```

### 5.2 为什么不做"自动下载并安装"

| 理由 | 说明 |
| --- | --- |
| **需要代码签名** | Windows 上静默安装**必须**是受信任的签名程序，否则系统会拦截 |
| **用户会不安** | **一个离线记账工具突然自己换了版本**——用户会怀疑"它是不是在偷偷连线" |
| **失败处理复杂** | 下载中断、安装失败、回滚……每一个都要处理 |

**所以项目选择了"告诉你 + 给链接"**：

> **这是"可控且诚实"的设计。**

### 5.3 更新清单怎么配（只差一个地址）

**代码已经写好了，你只需要**：

1. 把一个 `update.json` 放到任意可公开访问的地址：

```json
{
  "version": "1.1.0",
  "url": "https://你的域名/download",
  "notes": "新增预算与汇总图表"
}
```

2. 把地址写进代码（或设环境变量）：

```powershell
# 方式一：环境变量（临时测试用）
$env:LEDGER_UPDATE_URL = "https://你的域名/update.json"

# 方式二：写进代码常量（正式发布用）
# 编辑 src\main\services\security.service.ts 里的 DEFAULT_UPDATE_URL
```

3. **以后发新版只改那个 JSON 的 `version` 字段**，不用重发客户端。

**这个机制验证过**（`verify:update` 11/11 通过）：正常读到新版、同版本不误报、清单格式坏了不崩溃、连不上不卡死、没配地址时明确提示。

## 七、自测题

**1. 发布要解决哪三个问题？为什么很多人只想到第一个？**

**2. 代码签名是什么？没有它会发生什么？**

**3. 为什么这个项目不做"静默自动升级"？**

**4. 网站的 Open Graph 标签有什么用？**

**5. "上线了"和"有人能找到"之间差什么？**

---

### 答案与解析

**1.** ① **放哪**（文件托管）② **怎么给**（下载链接 + 安装信任）③ **怎么被找到**（SEO + 传播）。
→ 很多人只做 ①，然后发现"传上去了没人下载"——因为**信任问题（没签名）**和**曝光问题（没内容）**没解决。

**2.** 用你的私钥给安装包做数字签名，Windows 用公钥验证"这个包确实是你发的、且没被篡改"。
→ 没有签名：**每次打开都弹蓝色 SmartScreen 警告**，大量用户会以为中毒而放弃。**OV 证书约 ¥1000–2500/年，EV 约 ¥2500–5000/年（EV 立即不警告）。**

**3.** ① **需要代码签名**（Windows 静默安装必须是受信任的签名程序）；② **离线记账工具突然自己换版本会让用户不安**（会怀疑它偷偷联网）；③ 下载中断、安装失败、回滚等失败路径都要处理。
→ 所以选择"**告诉你有没有新版 + 给个链接**"，可控且诚实。

**4.** 让链接被分享到微信 / QQ / Twitter 时，**显示成带标题、描述、缩略图的卡片**，而不是一行干巴巴的网址。
→ **直接影响点击率**——这是"分享出去有没有人点"的关键。

**5.** 差三件事：**① 技术准备**（正确的 SEO 元素）、**② 主动提交**（去站长平台提交网址和 sitemap）、**③ 有内容**（别人搜"问题"时能看到你）。
→ **第 ③ 条最关键**：**没人搜你的产品名**（大家不知道它），大家搜的是**问题**。

## 八、术语表

| 术语 | 一句话解释 |
| --- | --- |
| **代码签名** | 用私钥给程序签名，让系统确认发布者身份 |
| **SmartScreen** | Windows 的"未知应用"拦截机制 |
| **OV / EV 证书** | 两种代码签名证书等级（EV 立即不警告） |
| **对象存储** | 专门存文件的云服务（OSS / COS / R2） |
| **SEO** | 搜索引擎优化，让别人搜得到你 |
| **Open Graph** | 分享到社交平台时的预览卡片标签 |
| **结构化数据** | 告诉搜索引擎"这是什么内容"的机器可读描述 |
| **sitemap** | 站点地图，告诉爬虫有哪些页面 |
| **canonical** | 指定正式网址，防重复内容 |
| **静默升级** | 后台自动下载并安装新版本 |
| **转化率** | 访问者里最终下载/使用的比例 |
